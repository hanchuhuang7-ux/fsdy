## 公开侦察与反制

侦察只读取公开配置中的兵种、x/z 坐标。它忽略 hp、alive、运行时刚体或假想未来数据。`counter` 同时计算重甲比例、突进比例、后排比例、后排近邻集群、横向中心和展开宽度。

- 盾卫 / 大锤占比至少 34% 时，提高弩手、掷弹兵、投石车权重，并将远程拉到后侧纵深。低军费先保证盾、射手、治疗协同，避免随机分散军费。
- 后排至少三人，且 3.5 米内近邻对足够多时，增加骑兵、游勇和投石车；近战使用猎杀或地图侧路迂回。
- 至少两名骑兵，或骑兵 / 游勇 / 掷弹兵占比至少 45% 时，提高长枪权重，并在扩军前预留前沿拒马，避免最后没有位置放防线。
- 高台偏重弓弩并优先坡顶位置；危桥偏重重锤、爆破和桥头道具；遗迹、沼泽使用外侧通道。种子控制配兵抽样、横排偏移和左右顺序，公开敌军分布也影响站位。

复盘从上一小局的公开 `result.report` 寻找敌方贡献最高兵种，并按己方阵亡单位初始位置、造价计算重创侧翼。下一局增加应对兵种，并调整部署侧重。三种性格都可利用复盘，`counter` 的配兵反应更强。

这仍是可解释的规则 AI，不是在线训练模型，也没有调用外部大模型。样本测试能验证反制比例和合法性，不能保证每个种子都优于人工阵型。

## Bo3 三局两胜

在“对战 / AI / 赛制设置”开启，适用于自由推演、人机、双 AI 和热座；试炼保持单关制。每局结束保留双方上一局初始阵型和公开战报。点击“复盘调阵 → 第 N 局”后，人类可微调，AI 根据战报重新部署。

系列赛锁定地图、军费、对战方式和军令开关；种子按小局递增。先获得两胜者提前结束，否则最多三局；若三局包含平局，比较胜局数，仍相同则系列赛平局。平局不会冒充任一方获胜。

战果页可导出 `frontline-bo3` 档案，包含每局配置和报告。单局回放仍单独导出。热座新小局重新封存布阵；上一局已经揭晓的报告是公开信息，当前秘密编队不会交给布阵 AI。系列赛保存在本次页面会话中，刷新前可导出档案留存。

```sh
npm run battle -- --red-ai counter --blue-ai maneuver --map ruins --bo3 --commander --out bo3.json
```

两边都是 AI 时，每局仍先同时侦察一次对方公开草案，再根据上一局报告定阵。混合 JSON / AI 评测中，人类 JSON 保持当前布局，AI 一侧复盘调阵。

## 统一统帅军令

默认关闭。配置示例：

```json
"commander": { "enabled": true, "aiTeams": ["blue"] }
```

每局每方 3 点，每道军令花 1 点，统一冷却 480 步，即 8 秒。位置必须是地图内地面。开关关闭、点数不足、冷却中、非法位置或战局结束都拒绝，不消耗点数。

| 军令               | 作用范围和持续时间                                 | 效果                                                            |
| ------------------ | -------------------------------------------------- | --------------------------------------------------------------- |
| 全军鼓舞 `inspire` | 点选位置 6 米内友军，5 秒                          | 移速 ×1.12，攻击冷却流逝速度 ×1.15                              |
| 集火令 `focus`     | 点选位置 8 米内友军，6 秒                          | 提高区域中心 4 米内敌军的目标权重，仍遵守射程、路径、冷却与友伤 |
| 固守盾阵 `fortify` | 点选位置 6 米内友方游勇 / 盾卫 / 长枪 / 大锤，5 秒 | 承伤 ×0.75、击退冲量 ×0.5                                       |

范围以接受军令时的位置确定；移动不让新单位自动加入，也不会无限延长增益。效果不叠加倍乘。场上会显示区域圈、短暂光效和受益单位足底圈。

人类选军令后点击地面；自由推演和揭晓后的热座可切换下令阵营。人机中玩家控制红方，蓝方由内置统帅下令；双 AI 演武中双方自动下令。暂停期间下令按钮禁用。

所有调用都进入 `battle.issueOrder(team,{type,x,z})`。AI 没有独立扣点或冷却捷径；返回 `{ok,entry}` 或 `{ok:false,reason}`。接受时统一刷新当前坐标，保证鼠标下令和按 tick 重演使用同一时刻的物理状态。日志条目为 `{id,team,type,x,z,tick}`，整局最多六条。

种子重演使用记录的军令日志，不再重新运行统帅决策。AI 自动下令也记录相同日志。完整轨迹帧保存点数、冷却、活动区域、单位增益标志和视听事件；因此可直接播放，也可按种子与军令时间重新算出相同战局。

## 视听与战力条

`audio.js` 不下载音频。弓弦、弩机、近战、格挡、重锤、冲锋、抛射、爆炸、治疗、布兵、开战、军令使用不同振荡器音型。首次用户交互前不创建 AudioContext；解锁失败不会阻止游戏。顶部可静音和调音量，偏好保存在本机。

最多 12 个并发音源、同一显示时段至多 4 个、同类至少间隔 55 ms；总线有压缩器和增益包络。模拟中的提示事件最多保留 24 条，同类按 tick 节流；它们不消耗战斗随机数。暂停不播放新提示，拖动时间轴会重置提示游标，减少跳转时的音效堆叠。

重锤、抛射和爆炸触发微震。只临时偏移渲染相机，随后恢复；不影响拾取坐标或物理。顶部可关闭，流畅画质也禁用。命中、格挡、治疗和军令光效沿用原 41 个特效上限，临时材质和批次继续回收。

实时战力按存活单位 `当前 HP / 最大 HP × 兵种造价` 计算，与超时判胜使用同一函数口径，道具不计入。条宽显示相对本方开场战力的保留比例，文字显示当前绝对战力。部署阶段显示完整兵力；热座封存阶段对方战力同样隐藏。

## 布阵、相机与收藏

脚底颜色与形状区分姿态：绿色推进箭头、蓝色坚守双杠、金色迂回双箭、玫红猎杀十字。布阵和暂停时显示；悬停提示包含姿态名。徽章由共享几何体组成，通过 `batches.js` 实例合批。

快捷视角包含斜角全览、正俯视布阵、跟随战线。跟随时优先平滑追踪中场存活单位重心，手动操作相机立即退出自动跟随。镜头与画质不改变战斗规则。

低频设置、混编和收藏收纳为抽屉。窄屏兵种为五列两排；右下“兵种 / 布阵”可弹出浮动兵种条，选中后自动收起，让战场保持可点选。

收藏夹有五个槽，只保存本方军队、道具、地图和名称，不保存隐藏对手。载入另一阵营镜像 x；地图不匹配或超军费时整次拒绝。试炼使用玩家关卡军费校验，不能借收藏绕过限制。收藏存于当前浏览器，清理浏览器数据会删除它们。

## 兼容与验证

0.1 / 0.2 / 0.3 布阵 JSON 均能导入，缺省姿态和军令字段会补默认值。回放格式 v1 仍接受旧引擎版本，完整轨迹补齐显示元数据；旧版本没有记录贡献时明确标记统计不可用，不伪造伤害。旧种子包按需调用冻结的对应旧模拟器和旧数据；原有依赖仍共享，不让新规则改写旧战果。新回放 v2 详情见 [回放格式](REPLAY_FORMAT.md)。

原有 48 项测试保持不变，新增 14 项，总计 62 项。新测试覆盖公开侦察隔离、多种反制比例、复盘站位、Bo3 提前获胜与平局、双方军令额度与冷却、局部增益与减伤、集火、军令记录重演、伪造日志、战力一致性、旧版种子与轨迹、收藏军费和音效节流。

性能、实测样本见 [PERFORMANCE.md](PERFORMANCE.md)；实测 Bo3 见 [v0.4-bo3-evaluation.json](v0.4-bo3-evaluation.json)。真实浏览器验证了约 700 像素窗口下的浮动兵种条、视角和手动交还、静音、军令扣点冷却、暂停、回放导出播放、Bo3 连续两局与收藏保存载入，错误日志为空。

没有增加在线联机、云端收藏、实时外部脚本指挥或学习模型。音色与震动强度仍需要不同设备的听感和观感反馈；确定性针对固定引擎、依赖、平台、配置、种子与军令日志，不承诺跨平台逐位相同。

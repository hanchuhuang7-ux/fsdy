# v0.5 · 演武擂台与外部智能体

版本 0.5.0，基于 0.4.0 继续开发。Three.js 0.187.0、Rapier compat 0.21.0、Vite 8.3.8 保持锁定；60 Hz 固定步、`batches.js`、3 米网格、每六步寻敌和既有 62 项测试保持原样。

## UI 模块

`src/main.js` 只协调主状态、布阵/战斗/回放阶段与渲染循环。UI 通过 `createX(app, actions)` 注入状态及动作，不反向导入 main，没有循环依赖。

| 模块 | 职责 |
| --- | --- |
| `ui/workshop.js` | 对局与回放导入导出、说明弹窗、本地档案 |
| `ui/hud.js` | 战力、军令、战果、Bo3、回放时间轴与高光 |
| `ui/deploy.js` | 布阵面板、诊断、混编、推荐阵型、试炼和收藏 UI |
| `ui/events.js` | 初始化与控件事件绑定 |
| `ui/battlefield.js` | 战场指针、框选、移动、触控防误放 |
| `ui/shortcuts.js` | 快捷键与输入焦点屏蔽 |
| `ui/arena.js` | 按需加载的循环赛设置、排行与矩阵 |

已有 DOM ID 保持。异步推演的结果整份提交；取消或输入已改变时不提交旧结果。地图、军费、对战方式与下一小局切换会等待 AI 规划完成后刷新视图。

## 算策 oracle

第四种内置风格。默认生成 4 个来自 counter / guardian / maneuver 与不同确定性部署种子的合法候选，使用同一公开敌军初始兵种、坐标、姿态。敌军 HP、alive、未来数据不会进入候选推演。

先各跑 360 步快筛，前两名各自从初始状态重新运行至结束或 5400 步。按己方残余战力优先，平手看净战力优势，再按候选序号固定决胜；总预算最多 `4×360 + 2×5400 = 12240` 步。每个试跑都释放物理世界。

`planOracle()` 是已初始化物理后的同步 CLI 入口；`planArmyAsync()` 逐 60 步让出主线程，网页显示快筛/验算进度，可取消。预算可在代码调用中收紧：候选 3–6、快筛 60–720、最终步数不低于快筛且最多 5400。网页默认使用固定预算。

双 AI 均先得到廉价公开草案，再各侦察一次，算策不会看到另一方尚未公开的最终阵型。热座不会调用公开侦察读封存对手。推演只是有限候选、有限种子的估计，不保证每局优于其他风格；它不联网调用模型，也不训练模型。

## 演武擂台

策略弹窗 →「演武擂台 / 循环赛排行」。参赛方可选内置四 AI、本浏览器五槽收藏、导入 JSON 的指定阵营。收藏与 JSON 保留所属地图，不能自动搬到不合法的地形；双方互换阵营时只镜像 x。

同一核心 `runTournament()` 同时服务网页与 CLI：

```sh
npm run tournament -- --config examples/tournament.json --out ranking.json
```

每两方在每张地图、每颗种子交换红蓝各打一局。支持 2–8 方、1–6 地图、1–10 个唯一种子，整个赛程最多 600 局，串行执行并可取消。比赛结束完整结算，没有把快筛结果当比赛结果。

输出 `frontline-tournament@1`：逐局战报、对阵矩阵、胜/平/负、胜率、得分率、平均残余战力、场均模拟用时与稳定 MVP 兵种。胜率是胜/局数；排行得分率为 `(胜+0.5×平)/局数`，同分按平均残余战力与原报名次序。MVP 是各局本方按有效伤害、友伤惩罚和治疗计算的贡献最高兵种的众数，平手按兵种键排序。

CLI 参赛方还可写成 `{"name":"我的军队","file":"army.json","team":"red"}`，相对路径基于赛程文件。收藏文件可用 `{"favoriteFile":"favorites.json","slot":0}`，槽位 0–4，文件为五槽数组或 `{ "slots": [...] }`。也可直接嵌入 `{name,units,props,team,map}`。

## 外部智能体

`npm run agent-battle -- --out-dir agent-results` 启动两个真实外部 Node Bot，以每 60 步一次的公开观察、受限军令响应完成 Bo3。另提供 Python 标准库示例。见 [AGENT_PROTOCOL.md](AGENT_PROTOCOL.md)；stdout JSON line、超时、越权拒绝、日志重演与进程信任边界均在那里定义。

## 诊断、高光与操作

布阵提示只分析传入的可见编队：前排比例、远程集群、高台位置、公开骑兵威胁；热座使用遮蔽后的视图。

引擎整局最多 24 条高光：首名阵亡、军令、单次桶/投石车范围伤害至少 150、战力净差至少 80 的反超。范围重创同类至少间隔 180 tick，反超至少 600 tick。记录纯整数 tick 和有限数值，不占随机数、不增物理刚体、不逐帧复制日志。它们放在最终结果与回放根部，旧回放可为空。

回放在时间轴显示刻度，同 tick 合并；点击跳到事件发生后第一个已完成的 10 Hz 记录帧，末帧夹紧。战况快报最多显示最近 5 条，可折叠。

桌面：Space 开战/暂停/继续，1/2/3 选鼓舞/集火/盾阵，Tab 循环视角，Ctrl/Cmd+Z 撤销，R 返回布阵。弹窗、输入框、select、contenteditable 或按键自动重复时屏蔽。

390px 下有「拖拽视角 / 点选布阵」单手开关，默认拖拽不放兵；点选模式关闭视角拖拽，滑动超过阈值也不放兵，pointercancel 与多指不同 ID 不触发布兵。回放时间轴、军令栏和战果在窄屏分开排列，长矩阵只在表格内部横滚。

## 兼容与构建

0.1–0.4 配置可迁移。v1 回放继续兼容 0.1/0.2/0.3；v2 接受 0.4 与 0.5。新增 `legacy/v0.4` 冻结旧引擎及数据，保留 v2 军令日志；旧种子按来源版本执行，不用新引擎重算旧战果。高光字段可缺省。

生产构建将锁定 Rapier 包的 base64 WASM 原字节转为独立 `.wasm` 静态资源，并校验外置文件与内嵌载荷完全一致。这样降低首次传输与 JS 解析体积，模拟代码及依赖不变。Node 直接使用原依赖。擂台和各旧引擎按需分块加载。

新测试覆盖推演合法性与确定性、异步等价和取消、循环赛统计与平局、真实子进程与超时、v2 回放重演、0.4 冻结兼容、高光定位、快捷键、无循环依赖，以及六地图 v0.4/v0.5 的 RNG/单位/弹道/尸体/军令/提示逐项一致。

实际测量、浏览器检查与当前局限见 [v0.5 验证记录](V0.5_VALIDATION.md)。

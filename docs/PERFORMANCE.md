保持同平台、锁依赖、45v45、种子 42、720 步、每六步快照、六次去一预热。对照源码为交接中的干净 v0.4（Sites 源提交 d26909ba251060c8c7ad80a54e8d74bb979be11e）。基准均独立运行，没有与测试或锦标赛并发。

两次交替均通过原 10% 门槛，全部样本保留：[before](performance-v0.5-before.json)、[after](performance-v0.5-after.json)、[首次 paired](performance-v0.5-paired.json)、[最终 paired](performance-v0.5-final-paired.json)。六地图自动测试另外验证新旧单位、弹道、尸体、军令和 RNG 一致。高光不新增刚体、不消耗随机数，不在帧快照重复复制。擂台与 oracle 只在明确发起推演时消耗预算，不进入普通实时战斗的额外规划循环。

生产构建把完全相同的 Rapier WASM 字节外置为静态资源，消除 base64 膨胀；不是降低精度或更换物理核心。原依赖大包警告仍存在，不能把物理 ms/步当成所有手机的 FPS 保证。

## v0.2 历史优化

优化面向两类开销：模拟中的全军遍历，以及士兵各个部件的独立绘制。没有通过降低物理模拟频率或改变画质档位下的兵种规则来换取速度。

### 模拟基准

当前电脑：Windows，Node.js 26.13.0。同一编队、种子和步数，45 对 45，游勇 / 盾卫 / 长枪 / 弓手 / 掷弹兵混编，运行 720 个固定物理步，每 6 步生成一次回放快照。运行 6 次，去掉第一次预热，取余下五次的中位数。

| 版本  | 每步中位数 | 720 步约耗时 |
| ----- | ---------: | -----------: |
| 0.1.0 |  0.6267 ms |     451.3 ms |
| 0.2.0 |  0.3432 ms |     247.1 ms |

这个用例的模拟耗时下降约 **45.2%**。原始样本见 [before.json](performance-before.json) 与 [after.json](performance-after.json)。运行 `npm run benchmark` 可以在自己的电脑上重新测量。

这是整体版本的负载对比。0.2 调整了寻敌频率、尸体数量和碰撞过滤，战斗轨迹也会变化，因此这不代表严格保持旧版战果的纯算法提速，更不是所有设备的帧率承诺。

### 渲染观察

默认 28 人、草甸、均衡画质的实测页面中，单位部件共 **360 个可见网格，合为 38 个实例批次**。计入地形与阴影等绘制后，观察到 189 次绘制调用。90 人样例则将 1,008 个部件合为 25 个批次，并完整跑完四倍速会战和回放。可以通过 `#viewport` 的 `data-actor-meshes`、`data-actor-batches`、`data-draw-calls` 读取当前帧数据；它们不是固定值。

### 已实施的改动

- 共享士兵几何体和材质，使用 Three.js `InstancedMesh` 提交身体、武器、道具和尸体部件。
- 寻敌每六步刷新一次；死亡目标立即重选。邻近避让与区域道具使用三米空间网格。
- 每步缓存活兵位置，避免在双重遍历中反复跨越 WASM 读取刚体状态。
- 当前画面复用快照对象，回放保留独立的 10 Hz 快照；战况文字降低刷新频率。
- 最多保留 24 具物理尸体，12 秒后移除。尸体仅与地形、掩体碰撞，不参与活兵、箭矢或尸体之间的接触求解。爆炸仍能推动尸体。
- 特效有数量上限，临时实例批次和材质会回收。
- 流畅 / 均衡 / 精细画质控制像素比和阴影；物理规则在三档之间保持一致。

Rapier 的 WASM 加载体积仍较大，首次打开需要下载和编译。移动端可以选择流畅画质，减少军队规模。大量炮弹、复杂接触和 4 倍速仍会增加负载。

# Unity 0.7.0 实际验证记录

验证日期：2026-11-17（Asia/Shanghai）；Unity 6000.6.9f1；Windows x64 + WebGL。这里保留未达标的中间结果、不同测法和实际限制。

## 已落地

- 128个预烘焙Mesh：64种资源 × 两级LOD；顶点色、平面法线、头盔肩甲、武器、马与倒马、投石车与碎车、五道具、单网格圆环。没有新增贴图；删除已无引用的Cube/Sphere/Cylinder资源。
- Shader支持实例阵营混色、半球补光、主辅光、距离雾和可选微风；渐变天穹覆盖俯视方向。
- 六图纯视觉生态与厚岩底座；装饰仅绘制矩阵，不创建Collider，不修改Data.Height、弹道、寻路或地面点击。独立装饰随机流不消耗战斗随机数。
- 三档画质控制草木密度90/280/560、粒子上限12/40/88、阴影距离22/42/65米；按地图和画质缓存静态矩阵。
- 投射物和24套六刚体布娃娃在开战前预热；碰撞体/标签缓存、接触查询索引、距离平方、预计算高度系数与3米网格查询。Core仍无UnityEngine依赖，60Hz不变。
- 桌面姿态与选中状态固定在底部按钮上方，滚动内容有独立边界。

## 自动与真实物理检查

- npm test：83项JS检查（77项冻结回归 + 6项工程约束）与68项C#核心检查，总计**151项通过**。
- npm run test:physics、原生checks、六图smoke退出成功；原生同构建重复对战均2279步蓝胜、完整轨迹往返校验通过。
- 对象池专项：256次投射物复用、32次布娃娃复用、24套上限/每套6刚体，0池耗尽；已记录帧保持独立。
- 0.6冻结适配器仍1847步红胜，完整战果JSON与原产物一致。0.6/0.7引擎身份分开；旧种子不使用新的物理对象顺序。
- 0.1–0.5原轨迹样例、0.6原始轨迹均可校验。0.6的309帧和0.7的381帧分别经Windows → WebGL工坊 → 导出，全量JSON一致，校验SHA见JSON报告。
- 新版外部双Bot Bo3：蓝方2:0，160次观察、12条军令、0拒收、0超时；完整回放随包。

每组丢弃1次预热，取5次实测中位数；45v45混合阵型、固定60Hz。预分配与fresh测法分列，不能把初始化工作从计时外移后仍称同一测法。

## 实机渲染与GC

Intel Arc B390；Windows Direct3D12；WebGL为ANGLE/OpenGLES3。均衡画质，每组360帧；正式版用于帧时，独立Development版用于GC。Unity6.6使用当前的Draw Calls Count记录实际绘制总数（含阴影与UI），不把BattleView的提交计数冒充Profiler Batches。参考[官方计数器定义](https://docs.unity.com/en-us/engine/6000.6/manual/analysis/profiler/counters-reference)。

Windows正式版约60FPS。WebGL的8ms中位帧时换算为125FPS，但毫秒计时量化限制了精度，不应解读为显示器精确刷新率。网页验收使用DPR=1以匹配标注的1280×800/390×844渲染尺寸；正常页面沿用最多DPR=2。

采样期间静态矩阵重建次数均为0，对象池耗尽均为0。WebGL GC中位数0仍有非零平均和峰值；整帧不是全程零GC。.NET核心预分配快照稳定状态100次调用零分配测试通过；Unity的线程分配API经8KB校准发现不可靠，未据此宣称原生零分配。

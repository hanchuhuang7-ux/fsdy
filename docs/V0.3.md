# v0.3 技术改造与玩法说明

版本：0.3.0。沿用 Three.js + Rapier，固定 60 Hz，十兵种、六地图、五道具。没有更换物理引擎或维护第二套命令行裁判。

## 三种内置布阵 AI

| 策略名     | 界面名称        | 规划行为                                                                           |
| ---------- | --------------- | ---------------------------------------------------------------------------------- |
| `guardian` | 磐石 · 稳健守阵 | 盾卫、长枪、弓弩和军医分纵深驻守；预留军费布置治疗旗、拒马                         |
| `maneuver` | 疾风 · 机动迂回 | 骑兵、游勇使用 `flank`，弩手使用 `hunt`；遗迹、沼泽优先外侧部署                    |
| `counter`  | 观势 · 环境反制 | 公开敌军至少有两名骑兵时增加长枪；否则危桥重锤与爆破，高台抢弓弩，沼泽用步兵与远射 |

AI 只读取地图、军费、种子和公开的兵种构成。它不读取未来轨迹、实时血量或隐藏的热座阵型。所有单位和道具都付费，遵守 60 人 / 12 道具 / 本方半场 / 实体间距。找不到合法位置时停止扩军，不放松规则。

规划器返回 `{units, props, style, spent, unused}`。同样的输入与种子产生同样的布局，使用独立的确定性随机序列，不消耗战斗 RNG。

玩家对战 AI 时，你控制红方，蓝方在开战前根据当前公开红方编队重新规划。AI 自动演武时，双方先形成不看对手的草案，再各获得一次侦察草案的机会，随后同时定阵。没有一方能无限读取另一方刚生成的最终反制结果。

这些是可解释的规则 AI，尚未进行大规模自博弈训练，也不承诺每种策略都胜过每一种人工阵型。

## 双人盲选热座

流程：选择热座 → 红方秘密布阵 → 封存红方 → 全屏交接 → 蓝方开始布阵 → 揭晓并开战。

封存阶段不向 Three.js 提交对方士兵或玩家道具，计数显示 `?`；禁用策略档案、导入导出与跨阵营切换；交接时清空撤销历史和选中部队，秘密编队不会自动写入浏览器存档。地图中立道具与地形仍可见。

这用于同一台设备上轮流操作。它没有网络对战，也没有加密或抵抗开发者工具检查内存的能力。战斗结束返回布阵时重新开始一轮盲选。

## 四种姿态

| 值        | 行为                                                                       |
| --------- | -------------------------------------------------------------------------- |
| `advance` | 按距离寻敌并推进，远程在射程内停下射击                                     |
| `hold`    | 不主动越过战线，保留攻击与治疗；被推出原阵位后，在无近身交战时返回开场锚点 |
| `flank`   | 偏好远程后排；遗迹走外门、沼泽走干燥侧路；其他开阔图使用侧向进路           |
| `hunt`    | 提高高价值远程及军医的目标权重，仍受距离、冷却和物理规则约束               |

左侧姿态用于后续单兵 / 整队放置。先框选或按兵种选择，再点击“应用姿态到选中”，可批量调整现有单位。试炼骑兵使用迂回，远程使用猎杀，军医驻守，其余单位推进。

## 批量排阵与战前预览

混编工具按兵种列表顺序生成方阵、横排或楔形。锚点是队伍前沿中心，后排向本方纵深延伸；单元间隔 2.5 米。可沿 `z=0` 镜像追加另一侧队伍。镜像会增加实际士兵数量并扣除军费，中心线上完全相同的点不会重复。

整队放置与移动都是原子操作：只要一名单位越界、重叠、超人数或超军费，整次操作不改变阵型。可撤销成功的编辑。选择“框选部队”后，在地面拖动矩形或逐个点击；“移动选中”后点击目标位置，会把队伍中心移动过去。取消选择恢复视角旋转。移动只作用于士兵，道具仍按原有方式单独放置或移除。

悬停现有士兵 / 道具或待放置位置会显示地面预览。攻击射程、高台对最近公开敌军的 +18% 加成、骑兵开场冲锋方向，以及炸药桶 4.2 米、治疗旗 3.2 米、地刺 1.15 米作用半径均可预览。射程线按地面高度采样，不延伸绘制到悬空平台之外。实际目标和朝向会在交战中变化，预览不保证每一发弹药都能命中。

## 战斗统计与 MVP

每个单位、每个道具只保存一小组累计数字；不新增逐伤害事件日志，也不逐帧汇总排行榜。结算时才聚合报告。

| 字段            | 统计口径                                                       |
| --------------- | -------------------------------------------------------------- |
| `damageDealt`   | 实际扣除的生命，包括士兵与可破坏道具、敌我双方；不计算过量伤害 |
| `damageTaken`   | 实际承受伤害；累计承伤可能因治疗超过初始生命                   |
| `healing`       | 实际恢复的生命；满血溢出治疗与复活不计                         |
| `kills`         | 击杀敌方士兵；友军阵亡不计入该值                               |
| `falls`         | 该单位自身坠崖或出界的次数                                     |
| `fallKills`     | 目标坠落前 180 步内最近一次伤害源为本单位 / 道具时的归因击杀   |
| `friendlyFire`  | `damageDealt` 中伤害己方的部分                                 |
| `friendlyKills` | 导致己方士兵阵亡的次数                                         |

炸药桶爆炸记在该桶名下，桶的阵营决定友伤；连锁爆炸各桶分别记账。地图中立桶的伤害保留在 `report.props`，不归给任何一支军队。不要把点燃桶的人和桶本身的爆炸伤害重复相加。

`result.report` 包含 `teams.red/blue`、每兵种 `byType`、完整 `units`、`props` 和 `mvp`。剩余战力仍按存活 HP 比例乘造价，统计不会改变胜负规则。

MVP 从士兵中选取，评分为：`damageDealt - 2*friendlyFire + 0.75*healing + 30*kills + 20*fallKills`，同分按 ID。界面显示双方分兵种战损贡献、全军合计、前八单位榜和 MVP；CLI 保留完整清单。

## 防卡死与残骸

前进单位每 30 步检查一次位移，连续三次小于 0.18 米且未眩晕时触发脱困。附近有墙、岩石或拒马时，创建入口、侧沿、出口绕行点；其他拥挤情况按固定 ID 方向尝试切线和后退。无额外随机数；桥面候选方向会检查地面存在，避免主动选择悬空方向。该局部方案不能保证消除任何数量下的全部拥堵，90 秒超时机制仍保留。

骑兵与投石车阵亡时，原六刚体五关节操作兵旁会显示倒马或散落车架。残骸是有界的程序化视觉模型，与布娃娃一起进入实例合批，并随 12 秒生命周期缩退移除；不增加新的物理刚体或关节，总计仍最多 24 组。残骸位置来自阵亡快照，未模拟独立马匹或车轮碰撞。

## 回放和评测

完整回放在战果面板导出，在“策略 / 导入导出 → 载入回放包 / 种子包”载入。完整轨迹按 10 Hz 保存；种子包保存初始配置并在同版本引擎中重新模拟。详情见 [回放格式](REPLAY_FORMAT.md)。

```sh
npm run battle
npm run battle -- --red-ai maneuver --blue-ai counter --map ruins --rounds 2 --out result.json
npm run battle -- --red file:red-army.json --blue ai:guardian --map highland --budget 2200 --rounds 5
npm run battle -- --red file:red-army.json --blue file:blue-army.json --out report.json
npm run battle -- --config examples/ai-duel.json --replay-out replay.json --out report.json
```

双方文件可以是单位数组、`{units,props}` 或完整旧版对局；完整对局按当前阵营提取对应数组。坐标仍必须位于该阵营半场，不会自动把红方坐标变成蓝方坐标。只传 `--config` 时保留双方，显式 `--red` / `--blue` 才覆盖对应阵营。`--rounds` 固定阵型、逐局增加战斗种子，最多 100 局；导出回放只允许单局。

外部脚本可从 `frontline-evaluation@1` 读取 `results[i].winner`、`remainingValue`、`report.teams`、`report.units`，据此修改下一轮 JSON。见 [AI 提示词](AI_PROMPT.md) 和 [评测实测](v0.3-ai-evaluation.json)。

## 工程验证与兼容边界

实际页面验证：旧版 0.2 JSON 导入后开战、玩家对 AI / 自动演武切换、AI 模式换图、红方混编封存与全屏交接、蓝方阶段数量隐藏及档案禁用、揭晓开战、按兵种批选后改姿态与删除、战果统计、完整回放导出提示、文件重新导入播放、时间轴与查看战果。过程中修复了自动演武换图被编辑锁拦截，以及窄窗口战果按钮被底部操作栏遮挡的问题。浏览器错误日志为空。

本次实际窗口约 701 像素宽，页面未出现横向溢出；浏览器的尺寸覆盖没有改变观测到的窗口宽度，因此不声称本版已经完成 390 像素真机验证。界面截图见 [v0.3](screenshots/v0.3-tactics.jpg)。

共 48 项自动测试：原有 26 项保持不变，新增 22 项。新增用例覆盖六地图 × 三策略 × 双阵营 × 四档军费的合法性、反制配兵、旧文件缺省姿态、驻守归位、后排猎杀、沼泽侧路、热座可见性、批量原子编辑、预览、贡献归因、完整战斗与轨迹重复、种子重演、危险键、无效轨迹、拒马脱困、桥面方向、残骸上限、双方独立 JSON CLI、试炼姿态与六图回放包。

性能保留 `InstancedMesh`、3 米网格、每六步寻敌、60 Hz 物理和 24 组尸体上限。伤害计数发生在事件时，排行榜只在结算时生成。新基准和原始样本见 [性能记录](PERFORMANCE.md)。

兼容旧 JSON 指格式与布阵数据可读，不代表跨版本战果不变。确定性测试针对相同引擎、依赖、平台、配置与种子；不承诺跨平台逐位一致。AI 规则和脱困路径升级后，同一旧阵型的战果可以变化。仍无在线联机、任意脚本实时指挥、桥面破坏或完整导航网格。
